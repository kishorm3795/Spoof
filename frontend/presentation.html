Context & Motivation

The Biometric Security Dilemma

Modern facial authentication must simultaneously prevent fraudulent presentation attacks while providing ultra-fast, friction-free verification on constrained edge or kiosk hardware.

⚠️ Vulnerability to Spoofing (Presentation Attacks)
  • 2D Static Spoofs: High-resolution printed photos and ID badge snapshots easily fool naive 2D cameras.
  • Digital Replay: Smartphones, tablets, and monitor video replays mimic genuine faces.
  • Impersonation Risk: Zero liveness checks mean stolen images grant physical door or kiosk access.
⚙️ The Deep Learning Dilemma on Edge Hardware
  • Heavy Compute: Multi-gigabyte ResNet/Transformer models demand expensive server-side GPUs.
  • Latency Spikes: Remote inference causes 500ms+ roundtrip network latency, hurting kiosk UX.
  • Black-Box Nature: Deep embeddings cannot be mathematically audited or projected back to visually inspectable components.
💡 Our Solution & Engineering Philosophy
A two-tier hybrid architecture: Offload active interactive liveness verification to the client browser via GPU-accelerated WebAssembly landmarks (zero server cost), while executing clean, explainable, and lightning-fast Principal Component Analysis (PCA) Eigenface spectral projection on the backend with vectorized nearest-neighbor retrieval.

Our Approach · Stage 1

Active Liveness & Interactive Challenge Protocol

Defeating static presentation attacks (printed photographs and static screens) via non-deterministic behavioral challenges.

Algorithmic Metric 1
Eye Aspect Ratio (EAR) - Blink Detection
Calculates relative vertical eye opening using 6 distinct 3D landmarks per eye:
EAR = (||p₁₆₀ - p₁₄₄|| + ||p₁₅₈ - p₁₅₃||) / (2 · ||p₃₃ - p₁₃₃||)
  • Closed Eye State: Triggered when EAR < 0.19.
  • Open Recovery State: Confirmed when EAR > 0.23.
  • Requires genuine physiological blink dynamics.
Algorithmic Metric 2
Normalized Head Yaw Deviation
Measures horizontal displacement of nose tip (landmark 1) relative to facial boundary landmarks (234 and 454):
Δ_yaw = [p₁.x - (p₂₃₄.x + p₄₅₄.x)/2] / FaceWidth
  • Turn Left: Confirmed when Δ_yaw < -0.12.
  • Turn Right: Confirmed when Δ_yaw > +0.12.
  • Dynamic baseline calibrated upon challenge initiation.
🛡️ Why Challenge-Response Beats Static Detectors
Static passive detectors can be tricked by high-resolution prints or cutouts. By introducing non-deterministic challenge prompts chosen dynamically at runtime, an adversary cannot pre-record a static gesture sequence. The challenge must be performed in real-time within the active camera session.
Our Approach · Stage 2

Face Localization & Illumination Invariance

Eliminating background contamination and lighting gradients before spectral projection.

Step 1: Localization
Haar Cascade Crop
Locates frontal face bounds with +20% contextual padding.

Why it matters: Prevents PCA from learning "white wall" or "dark office" as primary principal components.
Step 2: Resampling
Lanczos-4 Interpolation
Downsamples cropped face to standard 100 × 100 grayscale matrix (dimension d = 10,000).

Why it matters: Retains high-frequency edge detail while maintaining constant vector dimensionality.
Step 3: Equalization
CLAHE Normalization
Contrast Limited Adaptive Histogram Equalisation (clipLimit=2.0, tileGrid=8×8).

Why it matters: Equalizes localized lighting variations so shadows and bright glares do not skew recognition.
Pipeline Transformation: Raw Bytes ➔ PIL Decode ➔ OpenCV Haar Crop ➔ Resize 100×100 ➔ CLAHE Equalize ➔ Float32 [0, 1] Vector x ∈ ℝ¹⁰⁰⁰⁰
Our Approach · Stage 3

Spectral Mathematics: The Eigenfaces Pipeline

Dimensionality reduction via Principal Component Analysis using the Sirovich & Kirby surrogate covariance optimization.

Mathematical Formulation
1. Mean Face & Deviation Matrix
Given N face images stacked in X ∈ ℝ^(N × d):
Mean Face: Ψ = (1/N) ∑ xᵢ (shape: 10,000)
Deviation Matrix: A = (X − Ψ)ᵀ (shape: 10,000 × N)
Each column of A represents how a face deviates from the average human face.
The Core Algorithmic Trick
2. Surrogate Covariance (L = AᵀA)
Standard covariance C = AAᵀ is 10,000 × 10,000 (100M floats!).
Surrogate Covariance: L = AᵀA (shape: N × N)
Eigendecomposition: L vᵢ = λᵢ vᵢ
Instead of 100M entries, L is only N × N. Eigendecomposition executes in under 2 milliseconds!
Image Space Reconstruction
3. Eigenface Basis (U)
Multiply deviation matrix by surrogate eigenvectors and normalize:
uᵢ = A · vᵢ / ||A · vᵢ|| ➔ U ∈ ℝ^(10,000 × K)
Forms an orthonormal basis of K eigenfaces capturing primary facial variances.
Inference Projection
4. Face Space Representation (Ω)
Project any query face vector x into compact K-dimensional space:
Ω = Uᵀ(x − Ψ) (shape: K,)
A 10,000-pixel face image is compressed to just K = 50 spectral coefficients!
Our Approach · Stage 4

Vector Matching & Multi-Tier Decision Logic

Vectorized nearest-neighbor query in spectral face space combined with liveness verification gating.

Vector Metric
Cosine Distance in ℝᴷ Space
Measures angular deviation between query vector Ω_q and enrolled vector Ω_i:
D_cos(Ω_q, Ω_i) = 1 − (Ω_q · Ω_i) / (||Ω_q|| · ||Ω_i||)
  • Range: 0.0 (identical vector) to 2.0 (opposite).
  • Confidence Metric: max(0.0, 1.0 − D_cos)
  • Configured Threshold: 0.35
Decision Policy
Combined Turnstile Authentication
A strict AND-gate requirement for kiosk entry:
IF (Liveness == PASSED) AND (D_min ≤ 0.35):
➔ ALLOW (Identity Matched)

ELSE IF (Liveness == PASSED) AND (D_min > 0.35):
➔ DENY (Unknown Face)

ELSE:
➔ REQUEST VERIFICATION (Liveness Pending/Failed)
⚡ High-Efficiency Vector Store Architecture
Replaced heavy external vector databases with a tailored, pure-NumPy .npz store. It preserves zero external server dependencies, instant file persistence, and sub-millisecond vectorized batch queries across enrolled users.

Security & Engineering Rigor

Security Analysis & Current Limitations

Rigorous engineering audit identifying trust boundaries, threat models, and architectural constraints.

Client-Side Trust Boundary
Vulnerability: Landmark calculations run in client JavaScript. A malicious actor with DevTools access or an injected virtual camera driver could spoof landmark metrics.

Requirement: Server-side validation of raw video stream is required for zero-trust kiosk deployment.
Active vs. Passive PAD
Vulnerability: An active challenge protects against static photos, but remains susceptible to video stream injection, deepfake avatars, or realistic 3D silicon masks.

Requirement: Must pair with a passive Presentation Attack Detection (PAD) model assessing skin texture and reflections.
PCA Linear Capacity
Vulnerability: Eigenfaces rely on global linear variance. Extreme off-angle head poses or occlusions (masks/glasses) degrade matching accuracy compared to non-linear neural embeddings.

Requirement: Best suited for controlled frontal illumination or paired with deep feature extractors.
📋 ISO/IEC 30107-3 Biometric Compliance Standards
In enterprise biometrics, claims must be measured against formal metrics: APCER (Attack Presentation Classification Error Rate) and BPCER (Bona Fide Presentation Classification Error Rate). Our prototype is an active proof-of-concept demonstrating the multi-tier workflow, not a formally certified ISO PAD device.
